## 1 引言

### 1.1 编写目的

本文档规定 FT_Edit 上位机软件的总体设计、架构分层、模块职责、核心数据结构与关键实现机制，作为详细设计、编码实现、测试验证及后续维护的依据。读者为该软件的设计、开发、评审人员。

配套文档：

- 《技术文档》——开发环境、构建部署、JSON 配置格式规范、对外接口；
- 《软件开发文档》——目录结构、编码规范、扩展开发指南与必须遵守的实现约束。

### 1.2 项目背景

硬件产品"首件检查/功能测试"环节需要按顺序执行一系列通信命令（TBox AT 指令、I2C 写、I2C 写后读），并对响应进行判定。FT_Edit 是该流程的**上位机配置编辑器**：测试工程师在可视化界面中把命令组织成一个有序 Step 序列，配置每条命令的参数、响应期望值、失败处理方式及 Step 间延时，编辑结果以 JSON 文件形式保存，供测试执行端（或后续集成的执行引擎）加载运行。

### 1.3 软件定位与边界

FT_Edit 当前是**纯离线编辑器**：

- 负责：流程编辑、参数录入、响应判定配置、配置的保存/加载与合法性校验；
- 不负责：真实硬件通信与测试执行。代码中的 `FT_Test` 目前是执行引擎占位类（`runDocument()` 仅输出"执行引擎尚未实现"日志），`Widgets/Log*` 高性能日志组件已随工程编译但尚未挂接主界面。

### 1.4 术语

| 术语 | 含义 |
| --- | --- |
| Step | 流程中的一个测试步骤，外层列表中的一行，含使能、标题、命令组、延时 |
| 命令（Function） | Step 内单条通信指令：TBoxCommand / IicWrite / IicWriteRead |
| 组（Group） | 一个 Step 内全部命令的容器 `FT_FunctionGroup` |
| 软折行 | 组宽度不足时，布局器把命令自动打包到下一个视觉行 |
| 硬换行 | 用户通过右键菜单/拖拽显式插入的行断点，强制命令另起一行 |
| flat 序号 | 组内忽略换行的扁平命令序号（0..count） |
| Response Advance | 单条命令的响应判定与失败流转配置 |
| config | `FT_FunctionItemConfig`，一个 Step 的纯数据快照 |

## 2 总体设计

### 2.1 设计目标

1. **所见即所得**：命令在 Step 内按真实宽度流式排列，支持任意数量命令、自动折行与手动换行；
2. **入口与对象一致**：对哪个层级的对象操作，就在哪个层级提供入口（列表空白=Step、组空白=组内插入、命令=命令操作）；
3. 编辑全程**可撤销式直观操作**：双击、右键菜单、拖拽三种方式均可完成增删改与排序；
4. 编辑结果是**机器可读的版本化 JSON**，并对非法输入（非 HEX 载荷等）在保存时拦截；
5. 数据模型（`FT_Type.h`）与 Qt 控件解耦，便于未来执行引擎复用同一套结构。

### 2.2 运行环境

- 操作系统：Windows 10/11 x64；
- 开发框架：Qt 6.12 Widgets（仅依赖 `Qt6::Widgets` 模块）、C++17；
| 工具链 | 备注 |
| --- | --- |
| MSVC 2022（Visual Studio 生成器） | 主构建，产物 `build\Debug\FT_Edit.exe` |
| MinGW 13.1.0 + Ninja | 亦可构建（`D:\Qt\Qt6\Tools\mingw1310_64`） |
| 第三方库 | nlohmann/json（单头文件，随仓 `third_party/nlohmann/json.hpp`） |

### 2.3 用户角色与典型流程

测试工程师的典型操作链：

```
新建/加载配置 → 新建 Step → 向组内添加命令 → 填写命令参数
→ 打开 Response Advance 配置响应判定 → 调整命令换行/顺序（菜单或拖拽）
→ 设置 Step 标题/延时/使能 → 再增删 Step 并排序 → 保存 JSON
```

## 4 核心数据模型设计

定义于 [FT_Type.h](file:///e:/WorkSpace/FT_FirstSampltCheck/Module/FT_Type.h)。

### 4.1 命令数据（多态变体）

```cpp
using FT_FunctionData =
    std::variant<std::monostate,             // 空（反序列化遇到未知 type 时）
                 FT_TboxConfig,
                 FT_IicWriteConfig,
                 FT_IicWriteReadConfig>;
```

| 结构体 | 字段 |
| --- | --- |
| `FT_TboxConfig` | `command`(AT 指令，下拉可选 AT+CGSN/AT+CFUN?/AT+COPS?/AT+CSQ，也可手输)、`payload`(HEX 字节串)、`advance` |
| `FT_IicWriteConfig` | `port`(int)、`reg`(HEX)、`payload`(HEX)、`advance` |
| `FT_IicWriteReadConfig` | `port`、`reg`、`payload`、`readLength`(默认 1)、`advance` |

三种类型的工厂类型名字符串（菜单、工厂、MIME 共用常量）：

```cpp
kFtTypeTbox         = "TBoxCommand";
kFtTypeIicWrite     = "IicWrite";
kFtTypeIicWriteRead = "IicWriteRead";
```

### 4.2 响应判定 `FT_AdvanceConfig`

| 字段 | 取值/含义 |
| --- | --- |
| `toResult` | `DontCare`（默认，不判定）/ `Equal`（全等）/ `Range`（最小~最大区间）/ `StartWith`（前缀） |
| `target` / `targetMin` / `targetMax` | 期望值；Range 模式用 min/max，其余用 target；内容为空格分隔 HEX 字节 |
| `passMessage` / `failMessage` | 判定通过/失败时展示的消息 |
| `failTo` | 失败流转：`Stop`（默认，停止）/ `ContinueThis`（继续本 Step 后续）/ `ContinueAll`（继续后续 Step） |

### 4.3 文档结构

```cpp
// 一个 Step 内：每个内层 vector 是一条硬换行；
// 同一硬行内的命令在宽度不足时仍自动软折行。
using FT_FunctionLines    = QVector<QVector<FT_FunctionData>>;

struct FT_FunctionItemConfig {
    bool              enabled = true;
    QString           title;
    int               delayMs = 1000;
    FT_FunctionLines  lines;
};

using FT_FunctionDocument = QVector<FT_FunctionItemConfig>;  // 整篇配置
```

设计要点：**硬换行是数据的一部分**（二维数组的第二维切分），不是界面临时状态，因此保存/加载/拆分/合并均保持换行语义。

### 5.1 主窗口

- 窗口标题 `FT_Edit - Function Editor`，默认尺寸 1080×640；

```
Move Up
Move Down
─────────────────────────
Wrap to New Empty Step After   （在其后插入空 Step）
Merge with Next Step           （与下一 Step 合并；末行提示 No next step to merge）

```

### 5.5 命令组与命令控件

- 空组显示虚线提示框"Double-click or right-click to add a command"；空组**双击**追加默认命令；
- 三类命令均为横向排列的轻量控件，标题内嵌在控件顶部（Port/Reg/Payload/Read Len/Delay 等）；
- 每条命令右侧显示响应判定状态文字（DontCare 等），点击命令菜单中的 **Response Advance...** 弹出判定对话框。

### 5.6 Response Advance 对话框

- ToResult 下拉（DontCare / Equal / Range / Start With）；选 DontCare 时其下依赖区整体停用；
- Target：Equal/StartWith 时为多行 HEX 输入；Range 时切换为 Min/Max 两个输入框（QStackedWidget）；
- Pass Message、Fail Message 多行文本；FailTo 下拉（Stop/Continue This/Continue All）；
- OK/Cancel；确定时对 HEX 输入做规范化。

## 6 关键机制设计（架构核心）

### 6.1 四个层级的右键入口归属

"对象与入口一致"是本次交互重构的总原则，所有 Add/Step 动作按下表归属，**不允许在错误层级提供语义不符的入口**：

| 右键对象 | 菜单 | Add 动作的行为 |
| --- | --- | --- |
| 外层列表空白区 | 列表菜单 | `New Step with TBox Command / I2C Write / I2C Write+Read`——一律**新建独立 Step**；另有 Move Up/Down、Remove Selected、Clear All |
| Step 行边缘（标题/延时等非组区域） | Step 菜单 | Step 上移/下移、其后插空 Step、与下一 Step 合并、删除本 Step |
| 组内空白/行间 | **组菜单** `showGroupMenu` | `Add ...` 三项按现场 hitTest 落点插入；另含 New Empty Step After、Merge with Next Step |
| 命令本身 | 命令菜单 `showCommandMenu` | 顶部 `Insert Command After ▶` 子菜单（三类）插在该命令之后；其余为命令级操作 |

命令菜单完整项：`Insert Command After ▶` / `Response Advance...` / `Wrap to New Line` / `Join Previous Line` / `Split into New Step` / `Move Up` / `Move Down` / `Remove`。各项可用性由 `FT_FunctionGroup::refreshMenuStates()` 依据命令在组内的位置统一计算后通过 `FT_Function::setMenuState()` 下发。

### 6.2 组内流式布局：软折行 + 硬换行

`FtFlowBreakLayout`（继承 QLayout）持有扁平 `QLayoutItem*` 序列，断点记录在 `QSet<QWidget*> m_breaks`：

- `setGeometry` 时调用 `arrange()`：按命令的 `packMinimumWidth()` 贪心打包；遇到标记 breakBefore 的命令强制另起一行；
- 每个命令的最小宽度取内部固定控件宽之和与可扩展控件最小宽；固定宽度控件必须用 `maximumSize` 裁剪其 minimumSizeHint（如 combo 固定 160 但 hint 174），否则打包换行判定失效；
- 布局完成后缓存每行包含的 item 序号、各 item 几何与总高，供 hitTest 与插入符绘制复用；
- 高度变化时发 `heightChanged(int)`。

### 6.3 落点判定 hitTest

```cpp
struct FtGroupHit { int flat; bool hardBreak; bool valid; };
```

- 点击/拖放位置在**两条视觉行之间的间隙**：插入位置为下一行第一条命令，`hardBreak=true`；
- 在某行**最左 10px 热区**（`kHardZoneWidth`）：对该行强制换行插入（首行 flat=0 时不设断点）；
- 在**行内命令之间**：行内插入，`hardBreak=false`；
- **空组**：以组高度中线为界，中线下视为组尾；
- `caretRect()` 返回插入符矩形，拖拽移动时由 `showDropCaret()` 绘制竖线/断点提示。

所有插入动作**现场调用 hitTest 计算 flat**，不缓存行号，避免命令增删后索引失效。

### 6.4 高度自适应链

几何变化必须沿以下固定链条冒泡，任何一环断裂都会出现行高与内容不符：

```
FHintTextEdit 内容变化(heightChanged)
  或 FT_Function::updateFunctionHeight()
    → FT_FunctionGroup::relayout()/handleLayoutHeight()
        setFixedHeight(布局内容高) + emit requestResize()
      → FT_FunctionItem::adjustHeight()
          setFixedHeight(itemH)
          并回写 QListWidgetItem::setSizeHint(QSize(0, itemH+2))
```

`adjustHeight()` 用 `m_adjusting/m_pendingAdjust` 防重入；构造与 `applyConfig()` 结束后用 `QTimer::singleShot(0, adjustHeight)` 等布局稳定再测量。

### 6.5 外层行重排：固定槽 + config 轮转

QListWidget 的行控件通过 `setItemWidget` 绑定在 model index 上，`takeItem()`/`removeItemWidget()` 会立即 `deleteLater` 行控件。因此外层 Step 重排（上移/下移/行间拖拽）**严禁移动 QListWidgetItem**，统一在 `FT_Edit::moveFunctionRow(from, insertionPos)` 中处理：行槽原地不动，把相邻行的 `FT_FunctionItemConfig` 快照逐槽轮转，最后把移动行的 config 写回目标槽。

### 6.6 拖拽体系

两类 MIME（定义于 [FT_FunctionGroup.h](file:///e:/WorkSpace/FT_FirstSampltCheck/Module/FT_FunctionGroup.h)）：

| MIME | 载荷 | 来源 → 目标 |
| --- | --- | --- |
| `application/x-ft-node` | 树节点 NodeType（int） | 左树 → 组内 / 列表行间 |
| `application/x-ft-command` | 命令 config 的 JSON（QByteArray） | 组内命令 → 同组/异组/行间 |

- 命令拖拽源通过**进程内单一 static 引用**（匿名 namespace 内 `commandDragSourceRef()`）记录 `{group 指针, flat}`，提供 set/get/clear 三个函数；
- 命令跨组移动时，唯一的索引归一化在 `FT_Edit::onCommandIntoGroup()` 完成：先从源组删除，同源且目标在源之后时 flat 自减；
- 拖到列表行间（`onCommandDroppedToGap`）：源命令移出后，用其数据新建一个独立 Step，空源 Step 保留；
- 事件路由分工：命令及其子控件的 ContextMenu 由 `FT_Function::eventFilter` 处理（QTextEdit/QLineEdit 放行原生编辑菜单）；`FT_FunctionGroup::eventFilter` **只处理左键** MouseButtonPress/Move/Release（发起命令拖拽），不碰右键；组空白区右键直达 group 的 `contextMenuEvent`。

### 6.7 信号链路

- 命令 → 组：`contentChanged`、`requestRemove/requestMoveUp/requestMoveDown/requestWrap/requestUnwrap/requestSplitNewStep/requestInsertAfter(typeName)`、`requestResize`；
- 组 → Step/Edit：`contentChanged`、`structureChanged`、`requestResize`、`splitStepRequested(flat)`、`nodeDroppedAt(nodeType,flat,hardBreak)`、`commandDroppedAt(payload,flat,hardBreak)`、`requestInsertStepAfter()`、`requestMergeWithNext()`；
- Step → Edit：`contentChanged`、`removeRequested`、`moveUpRequested`、`moveDownRequested`、`insertStepAfterRequested`、`mergeWithNextRequested`、`splitStepRequested(flat)`；
- Edit 侧统一在 `createStep()` 内调用 `wireStepSignals()` 挂接，保证新建行与导入重建行的信号连接完全一致；
- 任何编辑信号最终都调 `m_project->markDirty()`（重建/加载期间由 `m_loading`、`m_suppressDirty` 抑制）。

### 6.8 Step 拆分与合并

- **拆分** `splitStepAt(row, flat)`：拍平组内全部命令并记录原硬换行集合；从 flat 处切成 head/tail 两份 config（保留各自断点），head 写回当前行，tail 在下一行新建 Step；
- **合并** `mergeStepWithNext(row)`：把下一 Step 首行拼到当前 Step 末行（行内合并），其余硬行整体追加；末行执行合并时仅状态栏提示"No next step to merge"，安全返回；
- **插入空 Step** `insertEmptyStepAfter(row)`：在其后插入默认 config（空组）。

### 6.9 重建期抑制与控件销毁

- `applyLines()`/`applyConfig()` 重建期间置 `m_loading=true`：不发 `contentChanged`、不调 `adjustHeight`；结束后复位并 `QTimer::singleShot(0, adjustHeight)`；
- `removeFunctionAt()` 等移除控件时必须先 `w->hide()` 再 `deleteLater()`，否则真实渲染会出现已删控件残影（deleteLater 到下一轮事件循环才析构）。

### 6.10 持久化与校验

- 保存：`FT_Project::collectDocument()` 逐行 `toConfig()` 收集 → `FT_Data` 转 JSON（`ordered_json`、缩进 2）→ 写文件 → `markClean()`；
- 保存前校验：TBox 的 payload、I2C 的 reg/payload 必须是**空格分隔的两位 HEX 字节**（如 `22 66`），空串允许；非法时弹窗指明 Step 标题与字段名，阻止保存；
- 加载：JSON parse 与结构解析分两层 try/catch，错误分别提示"不是合法 JSON"/"配置结构错误"；
- v1 兼容：item 没有 `lines` 而含单个 `function` 对象时，按单行单命令读入（见《技术文档》）。
