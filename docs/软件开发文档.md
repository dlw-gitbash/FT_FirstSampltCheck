## 2 开发环境

按《技术文档》第 2、4 节安装 Qt 6.12（msvc2022_64 或 mingw_64）、CMake ≥ 3.16、VS2022 或 MinGW 13.1 + Ninja。日常推荐命令：

```powershell
# MSVC（已配置 VS 环境）
E:\install\cmake-4.4.3\bin\cmake.exe -S . -B build -DCMAKE_PREFIX_PATH=D:/Qt/Qt6/6.12.0/msvc2022_64
E:\install\cmake-4.4.3\bin\cmake.exe --build build --config Debug --target FT_Edit
```

新增/修改代码后的**强制验证要求**：

1. 必须编译通过（命令行完整构建，不能只看 IDE 语法）；
2. 必须实际启动 `FT_Edit.exe` 冒烟（菜单、拖拽、换行高度、保存/加载）；
3. 不要执行 git commit（除非需求明确要求）；
4. 临时验证工程、截图等产物交付前删除。

## 3 编码规范（从现有代码归纳，新增代码保持一致）

1. **命名前缀**
   - 对外类名 `FT_` 开头（`FT_FunctionGroup`）；内部基础控件 `FHint` 开头；布局器 `FtFlowBreakLayout`；
   - 成员变量 `m_` 前缀（`m_loading`）；常量 `k` 开头（`kHardZoneWidth`）；
   - 工厂类型名统一使用 `Module/FT_Type.h` 中的常量 `kFtTypeTbox / kFtTypeIicWrite / kFtTypeIicWriteRead`，不要在业务代码里再写裸字符串 `"TBoxCommand"`。
2. **Qt 规矩**：QObject 子类带 `Q_OBJECT`；信号/槽用新式 `connect`；UI 文案全部 `tr(...)` 包裹；新增类放对应模块的现有头文件中（命令子类集中在 FT_Function.h）。
3. **类型模块 header-only**：`FT_Type.h` 只用 Qt Core + 标准库，不 include 任何控件头；枚举字符串映射用文件内 `inline` 函数。
4. **布局常量**：间距、热区宽度等魔数写在 .cpp 顶部匿名 `namespace { constexpr ... }`，并加中文注释说明含义。
5. **中文注释**写"为什么"（尤其 QListWidget 轮转、deleteLater、loading 抑制这类反直觉约束）；文件大节用 `// ====...` 分隔。
6. 头文件保护用 `#ifndef/#define/#endif`；日志独立头可用 `#pragma once`（沿用 `Widgets/LogEntry.h`）。
7. MSVC 兼容：避免 `lines.append({})` 这类 initializer_list 歧义写法，显式写 `lines.append(QVector<FT_FunctionData>{})`。
8. 输入限制在控件层做（SpinBox 范围/步进），格式校验统一收敛到保存路径（见 6.2）。

## 4 信号与高度链（改代码前先理解）

### 4.1 信号全景

```
FT_Function  ──► FT_FunctionGroup ──► FT_FunctionItem ──► FT_Edit(wireStepSignals)
 contentChanged   contentChanged       contentChanged       markDirty
 requestRemove    structureChanged     removeRequested      removeItem
 requestMove*     requestResize        moveUp/DownRequested moveItem*
 requestWrap      splitStepRequested   splitStepRequested   splitStepAt
 requestUnwrap    nodeDroppedAt        insertStepAfter…     insertEmptyStepAfter
 requestSplit…    commandDroppedAt     mergeWithNext…       mergeStepWithNext
 requestInsert…   requestInsertStep…
                  requestMergeWith…
```

- 每新建一行 Step（含导入重建）必须且只能在 `FT_Edit::createStep()` 中调用 `wireStepSignals()`，不要在别处零散 connect；
- 重建期间用 `m_loading=true` 屏蔽派生信号；`FT_Project` 侧另有 `m_suppressDirty`。

### 4.2 高度链（任何影响几何的改动都要沿此链冒泡）

```
FT_Function::updateFunctionHeight()
  → FtFlowBreakLayout 重算 → heightChanged
  → FT_FunctionGroup::handleLayoutHeight():setFixedHeight + emit requestResize
  → FT_FunctionItem::adjustHeight():setFixedHeight + QListWidgetItem::setSizeHint(h+2)
```

`FHintTextEdit` 文字行数变化经 `heightChanged` 触发同一链条。漏掉任何一环，外层行高就不会跟随内容。

### 4.3 事件路由分工（不要越界拦截）

| 事件 | 处理者 |
| --- | --- |
| 命令及其子控件右键（ContextMenu） | `FT_Function::eventFilter`（QTextEdit/QLineEdit 上放行原生菜单） |
| 组内左键按下/移动/释放（命令拖拽） | `FT_FunctionGroup::eventFilter`（**不处理右键**） |
| 组空白右键 | `FT_FunctionGroup::contextMenuEvent` → `showGroupMenu` |
| Step 行边缘右键 | `FT_FunctionItem` 自己的 customContextMenuRequested |
| 列表空白右键/双击/拖放/按键 | `FT_FunctionList` → 发信号给 FT_Edit |

## 5 常见开发任务指南

### 5.1 新增一种命令类型（完整清单）

假设新增 SPI 命令 `"SpiTransfer"`，按顺序改：

1. **FT_Type.h**
   - 加 `inline constexpr const char kFtTypeSpi[] = "SpiTransfer";`；
   - 定义 `struct FT_SpiConfig { ...; FT_AdvanceConfig advance; };`；
   - 把它加入 `FT_FunctionData` 的 `std::variant<...>` 参数列表（追加在末尾，不要插中间）。
2. **FT_Function.h / .cpp**
   - 新增 `class FT_SpiFunction : public FT_Function`，实现 `toConfig()/applyConfig()/openResponseAdvance()`，构造末尾调 `installCommandMenuFilters()`；
   - 在 `FtFunctionFactory::create()` 加 `if (typeName == kFtTypeSpi) return new FT_SpiFunction;`；
   - 参照现有子类放置控件、连接 `contentChanged`、在尺寸估算函数中登记固定宽控件。
3. **FT_Data.cpp**
   - `ftFunctionDataTypeName()` 加分支返回 `"SpiTransfer"`；
   - `ftFunctionDataToJson()` / `ftFunctionDataFromJson()` 加分支（字段读取用 `ftStrField/ftIntField`，缺省值显式给出；`advance` 缺省时给 `FT_AdvanceConfig{}`）。
4. **FT_Edit.h/.cpp**
   - `NodeType` 枚举加节点值；`buildTree()` 加树节点；
   - `typeNameFromNode()` 加映射；
   - 树右键菜单、列表空白菜单、组菜单、命令"Insert After"子菜单四处入口按需加项（**入口归属规则见 5.2**）；
   - 需要"新建独立 Step"时加 `addSpiItem()`（仿照 `addTboxItem`）；"加入当前 Step"复用 `addCommandToCurrentStep(kFtTypeSpi)`，无需新函数。
5. **校验**：新字段含 HEX 时，在 `FT_Edit::exportConfig()` 的校验循环与 `FT_Project::validatePayloadHex()` 中补分支（两处校验语义保持一致）。
6. **CMakeLists.txt**：如果新增了独立 .cpp/.h，登记进 `add_executable`（命令子类若按惯例写进 FT_Function.cpp 则无需改）。
7. 配置格式版本：纯新增可选字段/新增命令类型**不需要**升 `kFtConfigVersion`（旧执行端会忽略未知 type）；若修改了既有字段语义再递增，并在读取侧写兼容。
8. 全量构建 + 冒烟 + 用新类型保存/加载往返验证。

### 5.2 入口归属规则（加菜单动作时必须遵守）

| 想做的事 | 放哪里 |
| --- | --- |
| 新建一个独立 Step | 列表空白菜单（`New Step with ...`，图标 SP_FileDialogNewFolder）/工具栏 Insert |
| 在当前 Step 组内加命令 | 左树双击/右键（加入选中 Step 组尾）、组空白菜单（按 hitTest 落点） |
| 在某条命令之后插命令 | 命令菜单 `Insert Command After ▶` 子菜单（解决组被填满无空白可点） |
| 命令级动作（换行/移动/删除/判定） | 命令菜单 `showCommandMenu` |
| Step 级动作（上下移/拆分/合并/删除） | Step 菜单、组菜单分隔线下方（组菜单只放"其后插空 Step / 与下一 Step 合并"两个与位置相关的） |

不要在 Step 层放"加命令"动作，也不要在命令菜单里放"新建 Step"——保持"对象与入口一致"。

### 5.3 新增/修改一个配置字段（非新命令）

1. 结构体加字段并给默认值（FT_Type.h）；
2. `ftXxxToJson/FromJson` 加键，读取必须带 fallback；
3. 控件在对应 `FT_Function` 子类或 `FT_FunctionItem` 中加，`toConfig/applyConfig` 双向写；
4. 若影响控件尺寸：更新 `packMinimumWidth()/sizeHint()` 并验证换行；若影响高度：确认高度链被触发（必要时主动 `updateFunctionHeight()`）；
5. 《技术文档》第 5 节字段表与示例同步更新。

### 5.4 加一个 Step 级右键动作

在 `FT_FunctionItem.cpp` 构造里的 Step 菜单加 QAction → 定义/复用信号 → `FT_FunctionItem.h` 声明信号 → `wireStepSignals()` 中连接到 FT_Edit 新槽实现。组菜单需要同一动作时由 group 发信号、Item 转发（参照 `requestInsertStepAfter` 链路三层：group → item → edit）。

### 5.5 挂接日志面板（未来任务）

1. 在 FT_Edit 主布局加垂直 QSplitter，放入 `LogTableView`；
2. 实例化 `FT_Test`，`runDocument` 前 `collectDocument()`；
3. 把 `FT_Test::logMessage` 转到 `LogTableView::addLogInfo/...`（注意线程：执行引擎若在工作线程，日志通过队列信号投递，不要直接跨线程碰控件）；
4. 工具栏加运行/停止按钮并按 `testStarted/testFinished` 切换使能。

## 6 必须遵守的实现约束（踩坑清单，违反必出 Bug）

1. **外层行重排只能"固定槽 + config 轮转"**：禁止 `takeItem()` 后重新插入行控件——QListWidget 的 `setItemWidget` 控件绑定 model index，take 走即 `deleteLater`。统一走 `FT_Edit::moveFunctionRow()`。
2. **删控件先 hide 再 deleteLater**：`removeFunctionAt()`/`clearAllItems()` 等清理路径必须 `w->hide(); w->deleteLater();`，否则真实窗口出现已删控件残影重叠。
3. **重建期静默**：`applyLines/applyConfig` 期间 `m_loading=true`，不发 contentChanged、不 adjustHeight；结尾 `QTimer::singleShot(0, adjustHeight)`。
4. **高度必须冒泡到 sizeHint**：只 setFixedHeight 不回写 `QListWidgetItem::setSizeHint`，QListWidget 行高不变。
5. **插入位置现场算**：任何"在点击处插入"一律现场 `hitTest(localPos)`，不得缓存行号；跨组移动删除源后同源 flat 要自减并 qBound。
6. **拖拽源单例**：命令拖拽源只用匿名 namespace 中 `commandDragSourceRef()` 返回的单一 static 的 set/get/clear，禁止各自定义全局变量。
7. **打包宽度裁剪**：固定宽度控件参与换行计算时 `cwMin = qMin(cwMin, cwMax)`，防止 minimumSizeHint 大于固定宽导致永不换行。
8. **Delete 键保护**：焦点在 QTextEdit/QLineEdit/QAbstractSpinBox/QComboBox 时删除快捷键直接返回，避免删文本变成删 Step。
9. **无自动化测试时**：涉及结构/几何/序列化的改动，至少手工覆盖：同组拖拽、跨组拖拽、拖到行间、拆分、末行合并、保存/加载往返、v1 文件加载。

### 6.1 无 app.exec() 的临时验证 harness（如需要）

排查复杂交互时可在仓外/临时目录建最小 Qt 工程链产品源码。要点：

- 菜单/窗口截图用真实 Windows 平台插件，不要用 offscreen（offscreen 下弹窗 grab 可用但真实几何问题测不出来）；
- 不跑 `app.exec()` 时，`pump()` 辅助函数在处理完事件后必须显式
  `QCoreApplication::sendPostedEvents(nullptr, QEvent::DeferredDelete)`，
  否则 processEvents 的内部临时循环不投递外层 DeferredDelete，易误判生命周期问题；
- 用 `QMetaObject::invokeMethod` 触发信号时，无参信号不要传 `Q_ARG`（DirectConnection 下参数不匹配会静默失败）；
- 嵌套 `QTimer::singleShot` lambda 不要按引用捕获外层已析构局部，按值逐层传 `QWidget*`。

## 7 构建问题速查

| 现象 | 原因/处理 |
| --- | --- |
| `cannot open output file ft_harness.exe/FT_Edit.exe: Permission denied` | 上次运行的进程仍在（崩溃后残留）：任务管理器结束或 `Get-Process ft_edit|ft_harness | Stop-Process -Force` |
| 运行直接退出码 `0xC0000005`（3221225477） | 空指针/悬空指针；优先排查：信号 lambda 捕获已删 Step、嵌套定时器引用悬空、takeItem 后仍用旧控件指针 |
| MSVC 编译 initializer_list 歧义 | 显式写完整类型，如 `QVector<FT_FunctionData>{}` |
| MinGW 能编 / MSVC 报错（或反之） | 不要依赖编译器扩展；两套环境路径/PATH 不可混用 |
| 改了文件没被编译 | 新 .cpp 未登记进 `CMakeLists.txt`；或 AUTOMOC 未重跑（改 Q_OBJECT 后建议干净重建） |
| 改完行高显示不对 | 对照 4.2 高度链逐级确认信号是否发出、sizeHint 是否回写 |
