## 1 技术栈

| 类别 | 选型 | 说明 |

| 语言 | C++17（`CMAKE_CXX_STANDARD 17`，REQUIRED） | 使用 `std::variant` 等特性 |

## 4 构建与运行

### 4.1 方式一：MSVC / Visual Studio 2022（主方式）

"x64 Native Tools Command Prompt for VS 2022"或已配置 MSVC 环境的终端中：

```powershell
# 配置（首次）
E:\install\cmake-4.4.3\bin\cmake.exe -S . -B build -DCMAKE_PREFIX_PATH=D:/Qt/Qt6/6.12.0/msvc2022_64

# 编译（Debug）
E:\install\cmake-4.4.3\bin\cmake.exe --build build --config Debug --target FT_Edit

# 运行
.\build\Debug\FT_Edit.exe
```

需要把 Qt DLL 加入 PATH（或按下文部署）：

```powershell
$env:Path = "D:\Qt\Qt6\6.12.0\msvc2022_64\bin;" + $env:Path
.\build\Debug\FT_Edit.exe
```

### 4.2 方式二：MinGW + Ninja

```powershell
# 配置
E:\install\cmake-4.4.3\bin\cmake.exe -S . -B build_mingw -G Ninja `
  -DCMAKE_BUILD_TYPE=Debug `
  -DCMAKE_PREFIX_PATH=D:/Qt/Qt6/6.12.0/mingw_64 `
  -DCMAKE_CXX_COMPILER=D:/Qt/Qt6/Tools/mingw1310_64/bin/g++.exe

# 编译
E:\install\cmake-4.4.3\bin\cmake.exe --build build_mingw

# 运行（注意必须使用与 MinGW Qt 配套的运行时 PATH）
$env:Path = "D:\Qt\Qt6\6.12.0\mingw_64\bin;D:\Qt\Qt6\Tools\mingw1310_64\bin;" + $env:Path
.\build_mingw\FT_Edit.exe
```

> 注意：两套工具链的构建目录必须分开；不要混用 MSVC 的 Qt 与 MinGW 编译器。

### 4.3 部署（脱离开发环境运行）

使用 windeployqt 收集 Qt 依赖到 exe 同级目录：

```powershell
# MSVC 示例
D:\Qt\Qt6\6.12.0\msvc2022_64\bin\windeployqt.exe --debug --no-translations `
  --no-system-d3d-compiler .\build\Debug\FT_Edit.exe
```

随后将整个 `Debug` 目录打包即可在同架构 Windows 上运行。本程序无注册表/配置写入需求，除用户主动保存的 JSON 外不落地任何文件。

### 4.4 资源文件

图标经 `resources.qrc` 编译进可执行文件（Qt 资源路径 `:/resources/icons/*.png`），部署时无需额外携带图片。

## 5 配置文件格式规范（ft_config.json，version = 2）

### 5.1 总则

- 编码：UTF-8；缩进：2 空格（`json::dump(2)`）；键顺序保持写入顺序（`ordered_json`）；
- 顶层为对象，根键：

| 键 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `version` | int | 是 | 当前固定 `2` |
| `functions` | array | 是 | Step 数组，顺序即执行顺序 |

### 5.2 Step 对象（functions[] 元素）

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | Step 使能；执行端应跳过 false 的 Step |
| `title` | string | `""` | Step 标题 |
| `delayMs` | int | `1000` | 本 Step 执行前/后延时（毫秒）；UI 范围 0–60000 |
| `lines` | array<array<Command>> | `[]` | 二维命令数组：**每个内层数组是一条硬换行**；同一内层数组内多条命令为同一视觉行（宽度不足时编辑器软折行，不影响数据） |

> v1 兼容：若 Step 对象没有 `lines` 而含对象型 `function` 键，则按"单行单命令"读入。加载后保存会统一升级为 v2 结构。

### 5.3 命令对象（Command）

公共键 `type`（string）决定其余字段；未知/缺失 `type` 的对象在加载时被丢弃。

#### 5.3.1 TBoxCommand

```json
{
  "type": "TBoxCommand",
  "command": "AT+CGSN",
  "payload": "22 66",
  "advance": { ... }
}
```

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `command` | string | `""` | AT 指令文本（界面内置 AT+CGSN / AT+CFUN? / AT+COPS? / AT+CSQ 下拉，也可任意输入） |
| `payload` | string | `""` | 空格分隔的两位 HEX 字节；允许空串；保存时校验 |
| `advance` | object | 见 5.4 | 响应判定配置，缺省按默认值 |

#### 5.3.2 IicWrite

```json
{ "type": "IicWrite", "port": 0, "reg": "10", "payload": "01 02", "advance": { ... } }
```

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `port` | int | `0` | I2C 端口号 |
| `reg` | string | `""` | 寄存器地址，空格分隔 HEX 字节；保存时校验 |
| `payload` | string | `""` | 写入数据，空格分隔 HEX 字节；保存时校验 |
| `advance` | object | 默认 | 同上 |

#### 5.3.3 IicWriteRead

```json
{ "type": "IicWriteRead", "port": 0, "reg": "10", "payload": "", "readLength": 1, "advance": { ... } }
```

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `port` | int | `0` | I2C 端口号 |
| `reg` | string | `""` | 寄存器地址，HEX 字节 |
| `payload` | string | `""` | 读前写入数据，HEX 字节（可为空） |
| `readLength` | int | `1` | 期望读回字节数 |
| `advance` | object | 默认 | 同上 |

### 5.4 响应判定对象（advance）

| 键 | 类型 | 默认 | 取值/说明 |
| --- | --- | --- | --- |
| `toResult` | string | `"DontCare"` | `DontCare` / `Equal` / `Range` / `StartWith` |
| `target` | string | `""` | 期望响应（HEX 字节串）；Equal、StartWith 使用 |
| `targetMin` | string | `""` | Range 下限（HEX 字节串） |
| `targetMax` | string | `""` | Range 上限（HEX 字节串） |
| `passMessage` | string | `""` | 判定通过提示 |
| `failMessage` | string | `""` | 判定失败提示 |
| `failTo` | string | `"Stop"` | `Stop` / `ContinueThis` / `ContinueAll` |

枚举字符串无法识别时回退默认值（`DontCare` / `Stop`），不会导致加载失败。

### 5.5 校验规则（保存时）

1. TBoxCommand 的 `payload` 非空时，每个空白分隔 token 必须匹配正则 `^[0-9A-Fa-f]{2}$`；
2. IicWrite / IicWriteRead 的 `reg`、`payload` 非空时适用同一规则；
3. 校验失败弹窗格式：`Step "<title>": <字段> must be hex bytes separated by spaces (e.g. 22 66).`，并阻止保存；
4. 加载侧对结构宽松：非法 JSON、结构错误分别报错；未知键忽略，未知命令对象丢弃，数组中空行允许保留。

### 5.6 完整示例

```json
{
  "version": 2,
  "functions": [
    {
      "enabled": true,
      "title": "读取序列号",
      "delayMs": 1000,
      "lines": [
        [
          {
            "type": "TBoxCommand",
            "command": "AT+CGSN",
            "payload": "",
            "advance": {
              "toResult": "StartWith",
              "target": "38 36",
              "targetMin": "",
              "targetMax": "",
              "passMessage": "SN 格式正确",
              "failMessage": "SN 前缀不匹配",
              "failTo": "Stop"
            }
          }
        ],
        [
          {
            "type": "IicWrite",
            "port": 0,
            "reg": "20",
            "payload": "01",
            "advance": {
              "toResult": "DontCare",
              "target": "",
              "targetMin": "",
              "targetMax": "",
              "passMessage": "",
              "failMessage": "",
              "failTo": "Stop"
            }
          },
          {
            "type": "IicWriteRead",
            "port": 0,
            "reg": "21",
            "payload": "",
            "readLength": 2,
            "advance": {
              "toResult": "Range",
              "target": "",
              "targetMin": "00 00",
              "targetMax": "FF FF",
              "passMessage": "电压在范围内",
              "failMessage": "电压超范围",
              "failTo": "ContinueAll"
            }
          }
        ]
      ]
    },
    {
      "enabled": false,
      "title": "备用步骤",
      "delayMs": 500,
      "lines": []
    }
  ]
}
```

上例中：第 1 个 Step 的第一硬行有 1 条 TBox 命令，第二硬行有 I2C 写 + I2C 写读 2 条命令；第 2 个 Step 被禁用且为空组（编辑器允许）。

## 6 对外/对内接口

### 6.1 文件接口

- 保存对话框默认文件名 `ft_config.json`，过滤器 `JSON config (*.json)`；
- 执行端只需按第 5 节读取该 JSON；执行端写入的同版本 JSON 亦可被编辑器重新加载（未知键保留策略：重新保存时会丢弃编辑器不认识的键）。

### 6.2 进程内拖拽 MIME（编辑器内部约定，执行端无需关心）

| MIME 类型 | 载荷 |
| --- | --- |
| `application/x-ft-node` | 左侧树节点类型：1=Functions 根、2=TBoxCommand、3=IicWrite、4=IicWriteRead |
| `application/x-ft-command` | 单条命令对象序列化后的 JSON 文本（即 5.3 的 Command 对象） |

### 6.3 未来执行引擎接口（FT_Test，当前占位）

[FT_Test.h](file:///e:/WorkSpace/FT_FirstSampltCheck/Module/FT_Test.h) 已定义执行端契约：

```cpp
public slots:
    void runDocument(const FT_FunctionDocument& doc);
    void stop();
signals:
    void testStarted();
    void testFinished(bool passed);
    void logMessage(const QString& msg);
```

执行端实现应：按 `functions` 数组顺序跳过 `enabled=false` 的 Step；按 `lines` 内层顺序发送命令；按 `advance.toResult` 比对响应并依据 `failTo` 决定流转；`delayMs` 为 Step 延时。

## 7 验证方式

当前工程无自动化单元测试工程。版本交付前的最低验证（手工冒烟）：

1. MSVC 构建 `cmake --build build --config Debug --target FT_Edit` 零错误零警告地通过；
2. 启动 `build\Debug\FT_Edit.exe`；
3. 左树双击/右键三类命令加入当前 Step；组空白右键按行间/行内落点插入；命令右键 Insert After 子菜单插入；
4. 命令拖拽：同组换行、跨组移动、拖到列表行间生成新 Step；
5. Step：插入空 Step、与下一 Step 合并（末行合并应仅提示不崩溃）、从命令拆分成新 Step、上移下移、删除；
6. Response Advance 四种模式切换（Range 显示 Min/Max）；
7. 输入非法 HEX（如 `zz`）保存应被拦截；合法配置保存后重新加载内容一致（含硬换行行数、延时、使能状态）；
8. 加载 v1 格式（单 `function` 对象）文件应成功迁移显示。
